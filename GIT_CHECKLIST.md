# 🌐 Инструкция-чеклист по публикации проектов на GitHub

Этот интерактивный гид поможет с нуля развернуть репозиторий, защитить свои данные и обновлять файлы в будущем. Отмечайте выполненные шаги крестиками `[x]`.

---

## 🛠️ Шаг 1. Подготовка репозитория на сайте GitHub
- [x] **1. Создать новый репозиторий**
  * Зайти в свой профиль на [GitHub](https://github.com).
  * В правом верхнем углу нажать **`+`** -> **New repository**.
- [x] **2. Настроить видимость и чистоту репозитория**
  * Задать имя проекта (например, `my-python-template`).
  * **Важно:** Оставить настройки пустыми — **НЕ** ставить галочки на *Add a README*, *Add .gitignore* или *Add license*.
  * Нажать **Create repository**.
- [x] **3. Скопировать ссылку на репозиторий** https://github.com/VictoriaPulman/practice.git
  * Скопировать URL-адрес из появившегося окна (ссылка, которая заканчивается на `.git`).

---

## 💻 Шаг 2. Команды в терминале VS Code при ПЕРВОЙ публикации
Откройте вашу чистую рабочую папку в VS Code, запустите встроенный терминал (`Ctrl + \``) и отмечайте выполненные команды:

- [x] **1. Инициализировать Git в локальной папке:**
  ```bash
  git init
  ```
- [ ] **2. Добавить все файлы проекта под контроль Git:**
  ```bash
  git add .
  ```
- [ ] **3. Сделать первый снимок (коммит) проекта:**
  ```bash
  git commit -m "First commit: clear template"
  ```
- [ ] **4. Связать локальную папку с вашим репозиторием на GitHub:**
  * *Вместо ссылки ниже подставьте СВОЮ ссылку из Шага 1:*
  ```bash
  git remote add origin https://github.com/VictoriaPulman/practice.git
  ```
- [ ] **5. Создать главную ветку и отправить файлы на сервер:**
  ```bash
  git branch -M main
  git push -u origin main
  ```

---

## 🆙 Шаг 3. Как добавить новые файлы или обновить старые (Например, README.md)
Если репозиторий на GitHub уже успешно создан, а вы позже добавили в папку новый файл (например, `README.md`) или просто изменили код в ноутбуке, повторно настраивать Git не нужно. Выполните три простые команды:

- [x] **1. Заставить Git заметить новые файлы или изменения:**
  ```bash
  git add .
  ```
- [x] **2. Зафиксировать изменения и написать комментарий:**
  ```bash
  git commit -m "Add README.md description"
  ```
- [x] **3. Отправить обновления на сервер одной короткой командой:**
  ```bash
  git push
  ```

## ⚠️ Возможные проблемы и их решение

### Ошибка: `push declined due to email privacy restrictions (GH007)`
**Причина:** На GitHub включена защита, которая запрещает публиковать коммиты, содержащие ваш реальный личный email-адрес.

**Решение (на примере пользователя VictoriaPulman):**
- [ ] **1. Скопировать анонимный email от GitHub**
  * Перейти в настройки скрытых адресов: [://github.com](https://github.comsettings/emails).
  * В блоке *Primary email address* скопировать анонимный адрес (например: `81351659+VictoriaPulman@://github.com`).
- [ ] **2. Указать Git использовать этот скрытый адрес в терминале:**
  ```bash
  git config user.email "81351659+VictoriaPulman@://github.com"
  ```
- [ ] **3. Обновить автора уже созданного коммита, чтобы применить новый email:**
  ```bash
  git commit --amend --reset-author -m "First commit: clear template"
  ```
- [ ] **4. Повторить отправку на сервер:**
  ```bash
  git push -u origin main
  ```

## 🚨 Чрезвычайная ситуация: Что делать, если случайно добавил окружение раньше времени?
Если `.venv` попал в индекс после `git add .`, выполни экстренную очистку и настройку через терминал:

- [ ] **1. Удалить папку окружения из индекса Git (на ПК файлы останутся на месте):**
  ```bash
  git rm -rf --cached .venv
  ```
- [ ] **2. Создать файл `.gitignore` и прописать туда `.venv` через терминал:**
  ```bash
  touch .gitignore
  echo ".venv/" >> .gitignore
  ```
- [ ] **3. Вернуться к пунктам твоего Шага 2 (заново добавить файлы и продолжить):**
  ```bash
  git add .
  git commit -m "First commit: clear template with gitignore"
  git remote add origin https://github.com
  git branch -M main
  git push -u origin main
  ```
